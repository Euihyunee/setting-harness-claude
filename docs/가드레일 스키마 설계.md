# 가드레일 로그 테이블 설계

> 대상: dinai-db
> 적재 정책: **가드레일에 걸린 케이스만** 저장 (정상 통과는 적재하지 않음)
> 목적: AI 호출 가드레일 위반 이력을 적재하고, 기존 `dinai.access_logs` / `dinai.conversations` 와 cross-trace 분석 가능하도록 함

---

## 1. 컬럼 정의
- 2026-04-30 : 대리님과 이야기하여 conversaion_id 는 제거하도록 결정. 대화 말고 다른 곳에서 가드레일을 적용한 부분이 있기 때문. 

| 컬럼                         | 타입          | NULL     | 설명                                                                   |
| -------------------------- | ----------- | -------- | -------------------------------------------------------------------- |
| `id`                       | uuid        | NOT NULL | PK. 기존 로그 테이블 컨벤션 (uuid) 따름                                          |
| `employee_id`              | varchar     | NOT NULL | 사용자 사번. 사용자명은 조회 시 조인                                                |
| `dept_id`                  | varchar     | NULL     | 부서 ID. 부서명은 조회 시 조인                                                  |
| `ip_address`               | varchar(45) | NULL     | 호출자 IP                                                               |
| `conversation_id`<br>(제거됨) | uuid        | NOT NULL | **개별 대화의 conversation_id**. `dinai.conversations.id`                 |
| `trace_id`                 | varchar(32) | NULL     | 요청 단위 트레이스 키                                                         |
| `check_type`               | varchar(20) | NOT NULL | `INPUT` / `OUTPUT`.                                                  |
| `result`                   | varchar(50) | NOT NULL | 가드레일 위반 결과 분류 (예: `BLOCKED`, `MASKED`, `GUARDRAIL_INTERVENED`).      |
| `violation_details`        | jsonb       | NOT NULL | **위반 요약**만 저장. 응답 원본 통째 적재 금지. 정책 식별자·카테고리·매칭 키워드 수준, 상세 조회 시 보여줄 예정 |
| `created_at`               | timestamptz | NOT NULL | 적재 시각                                                                |

### 1.1 삭제 검토 컬럼

아래 두 컬럼은 식별 가치가 없다고 판단되면 제거 예정.

| 컬럼 | 타입 | NULL | 설명 / 보류 사유 |
|---|---|---|---|
| `guardrail_id` | varchar(50) | NOT NULL | 적용된 가드레일 식별자 (Bedrock Guardrail ID 등). 단일 가드레일만 운영 시 불필요 |
| `guardrail_version` | varchar(10) | NOT NULL | 가드레일 버전. 버전 비교 분석이 필요 없으면 불필요 |

## 2. DDL

```sql
CREATE TABLE IF NOT EXISTS dinai.guardrail_logs (
    id                 uuid PRIMARY KEY NOT NULL,

    employee_id        varchar NOT NULL,
    dept_id            varchar,
    ip_address         varchar(45),
    conversation_id    uuid NOT NULL,
    trace_id           varchar(32),

    check_type         varchar(20) NOT NULL CHECK (check_type IN ('INPUT','OUTPUT')),
    result             varchar(50) NOT NULL,

    -- (삭제 검토) 단일 가드레일·단일 버전 운영 시 제거
    guardrail_id       varchar(50) NOT NULL,
    guardrail_version  varchar(10) NOT NULL,

    violation_details  jsonb NOT NULL,

    created_at         timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_guardrail_logs_employee
    ON dinai.guardrail_logs (employee_id, created_at);
CREATE INDEX IF NOT EXISTS idx_guardrail_logs_created
    ON dinai.guardrail_logs (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_guardrail_logs_result
    ON dinai.guardrail_logs (result);
CREATE INDEX IF NOT EXISTS idx_guardrail_logs_conversation
    ON dinai.guardrail_logs (conversation_id);
CREATE INDEX IF NOT EXISTS idx_guardrail_logs_trace
    ON dinai.guardrail_logs (trace_id);
CREATE INDEX IF NOT EXISTS idx_guardrail_logs_violation_gin
    ON dinai.guardrail_logs USING GIN (violation_details);
```

---

## 3. 인덱스 의도

| 인덱스 | 용도 |
|---|---|
| `idx_guardrail_logs_employee` (employee_id, created_at) | 사용자별 시간순 위반 이력 조회 |
| `idx_guardrail_logs_created` (created_at DESC) | 최근 발생 순 대시보드/리포트 |
| `idx_guardrail_logs_result` | 결과 분류별 필터링 |
| `idx_guardrail_logs_conversation` | 특정 대화 내 위반 흐름 추적 |
| `idx_guardrail_logs_trace` | `access_logs` 와 요청 단위 cross-trace 조인 |
| `idx_guardrail_logs_violation_gin` (GIN) | `violation_details` 내부 정책·카테고리 검색 |

## 4. 조회 패턴 예시

### 4.1 특정 사용자의 최근 위반 이력
```sql
SELECT created_at, check_type, result, violation_details
FROM dinai.guardrail_logs
WHERE employee_id = :emp_code
ORDER BY created_at DESC
LIMIT 50;
```

### 4.2 access_logs 와 trace_id 조인 (요청 단위 상관분석)
```sql
SELECT a.created_at, a.access_path, a.result AS access_result,
       g.check_type, g.result AS guardrail_result, g.violation_details
FROM dinai.access_logs a
JOIN dinai.guardrail_logs g
  ON a.trace_id = g.trace_id
WHERE a.created_at >= now() - interval '1 day';
```

### 4.3 특정 대화의 위반 이력 + 입력 본문 조회 (조인)
```sql
-- 입력 본문은 별도 테이블 (conversations / 메시지) 와 조인해서 가져옴
SELECT g.created_at, g.check_type, g.result, g.violation_details,
       c.title
FROM dinai.guardrail_logs g
JOIN dinai.conversations c ON c.id = g.conversation_id
WHERE g.conversation_id = :conversation_id
ORDER BY g.created_at;
```

### 4.4 violation_details 내부 정책 검색 (GIN 인덱스 활용)
```sql
SELECT *
FROM dinai.guardrail_logs
WHERE violation_details @> '{"policies": ["TOPIC:FINANCIAL_ADVICE"]}';
```
