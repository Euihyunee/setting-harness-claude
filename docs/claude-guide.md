# Claude Code 사용 가이드 (DINAI 프로젝트용)

이 문서는 DINAI 멀티 레포 프로젝트에서 Claude Code를 효과적으로 다루기 위한 실전 가이드. 명령어를 처음 보는 사람도 바로 따라 할 수 있도록 **꼭 필요한 것만** 추림.

> [!info] 이 가이드의 범위
> Claude Code 일반 사용법 + 이 레포에 미리 세팅된 에이전트 6종 / 스킬 4종 / 훅 4종을 어떻게 활용하는지에 집중. 마크다운 작성 규칙은 [docs/markdown-style-guide.md](markdown-style-guide.md) 참조.

---

## 1. 가장 먼저 외울 슬래시 커맨드 6개

프롬프트 입력창에 `/` 를 치면 자동완성 목록이 뜬다. 외우기 부담스러우면 **이 6개만** 알아도 90% 커버.

| 커맨드          | 언제 쓰나                                  | 효과                          |
| ------------ | -------------------------------------- | --------------------------- |
| `/help`      | 사용법 까먹었을 때                             | 도움말 + 사용 가능 커맨드 목록          |
| `/clear`     | 대화가 길어져 답변이 느려질 때 / 새 작업 시작할 때         | 대화 히스토리·컨텍스트 초기화 (메모리는 유지됨) |
| `/agents`    | 에이전트 목록 보고 싶을 때                        | 등록된 서브에이전트 6종 확인 + 편집       |
| `/model`     | 모델 바꾸고 싶을 때 (Opus ↔ Sonnet ↔ Haiku)    | 모델 선택 UI                    |
| `/config`    | 테마·키바인딩 등 설정 변경                        | 설정 화면                       |
| `/init`      | 새 폴더에서 시작할 때                           | `CLAUDE.md` 자동 생성           |

> [!success] 실전 팁
> 한 작업이 끝나면 `/clear` 로 컨텍스트를 비우고 새 작업을 시작하면 응답 속도가 눈에 띄게 빨라진다. 메모리(`memory/` 폴더)는 `/clear` 해도 유지되니 안심.

## 2. 입력창에서 쓰는 특수 prefix

슬래시 말고도 입력창에서 쓰는 짧은 기호들. 자주 쓰는 것만 추림.

| prefix       | 의미                                      | 예시                                     |
| ------------ | --------------------------------------- | -------------------------------------- |
| `!`          | 셸 명령을 직접 실행해서 결과를 대화에 붙여넣기              | `!git status`                          |
| `@`          | 파일 경로 자동완성 (Claude가 그 파일을 읽음)           | `@docs/markdown-style-guide.md 요약해줘`   |
| `#`          | 빠른 메모 — 그 자리에서 `CLAUDE.md` 등에 메모 추가     | `#커밋 메시지에 이모지 쓰지 말기`                   |
| `Esc`        | 진행 중인 응답 중단                             | (키보드)                                  |
| `Esc Esc`    | 직전 메시지로 되돌아가서 수정                        | (키보드)                                  |
| `Shift+Tab`  | 권한 모드 토글 (기본 → accept-edits → plan)     | (키보드)                                  |

> [!warning] `!` 사용 주의
> `!` 로 실행한 명령은 사용자 권한으로 즉시 실행됨. `rm`, `git push --force` 같은 파괴적 명령은 직접 입력하지 말고 Claude에게 시켜 권한 프롬프트를 거치는 편이 안전.

## 3. 이 프로젝트의 에이전트 6종

`/agents` 로 확인할 수 있는 전담 팀원들. 각자 **담당 폴더만** 수정 가능 (소유권 규칙은 [CLAUDE.md](../CLAUDE.md) 참조).

| 에이전트         | 담당 영역                                    | 호출 시점                                |
| ------------ | ---------------------------------------- | ------------------------------------ |
| `frontend`   | `dinai-client/` (React 19 + Vite)        | UI 작업 / 페이지 추가 / 상태관리                |
| `core-api`   | `dinai-core-api/` + `dinai-db/`          | Spring Boot API · DB 스키마 · MyBatis   |
| `ai-api`     | `dinai-ai-api/` (FastAPI + LangChain)    | 챗봇 / RAG / 벡터검색 / Bedrock 연동         |
| `devops`     | Dockerfile · Jenkinsfile · nginx · 컴포즈 파일 | 배포 / CI/CD / 인프라 설정                  |
| `security`   | 전체 (읽기 전용)                               | 코드 변경 후 OWASP Top 10 점검              |
| `code-status` | 4개 레포 코드 현황 분석 (읽기 전용)                  | "지금 진행 상황 요약해줘" 같은 메타 질문             |

### 3.1 에이전트 호출하는 법

두 가지 방식. 보통은 **방식 A** 만 알면 됨.

**방식 A — 자동 위임 (추천)**

그냥 평소처럼 자연어로 요청하면 Claude가 알아서 적절한 에이전트에게 넘긴다.

```text
프론트엔드 로그인 페이지에 비밀번호 표시 토글 버튼 추가해줘
→ 자동으로 frontend 에이전트가 처리
```

**방식 B — 명시적 지정**

특정 에이전트를 콕 집어 시키고 싶을 때.

```text
@core-api dinai-db에 user_session 테이블 추가하고 마이그레이션 SQL 작성
```

> [!info] 병렬 작업 시키는 법
> "프론트는 X, 백엔드는 Y, AI는 Z 동시에 진행해줘" 라고 하면 3개 에이전트가 **병렬로** 동시 작업. 시간 절약에 유용.

## 4. 미리 세팅된 스킬 4종

스킬 = 자주 하는 작업을 한 줄 명령으로 묶어둔 매크로. 슬래시 커맨드처럼 `/<스킬명>` 으로 호출하거나, "전체 검증 돌려줘" 처럼 자연어로 시켜도 알아서 호출됨.

| 스킬                  | 하는 일                                                    | 언제 쓰나                          |
| ------------------- | ------------------------------------------------------- | ------------------------------ |
| `test-all`          | 4개 레포 전체 type-check · lint · test · build 실행            | 큰 변경 후 / 커밋 직전                 |
| `security-audit`    | OWASP Top 10 기반 전체 코드베이스 보안 스캔                          | 인증·DB·외부 API 코드 변경 후           |
| `check-ownership`   | 변경된 파일이 담당 에이전트 소유 경계를 넘지 않았는지 확인                       | 멀티 에이전트 작업 직후                  |
| `agent-team-setup`  | 새 프로젝트에 CLAUDE.md · 에이전트 정의 · 설정 일체 자동 생성               | 신규 레포 셋업 시 (이 프로젝트는 이미 끝나서 불필요) |

**호출 예시**

```text
/test-all
/security-audit
방금 변경한 파일들 소유권 체크해줘    ← check-ownership 자동 호출
```

## 5. 자동으로 도는 훅 4개 (그냥 알고만 있으면 됨)

`.claude/hooks/` 에 있는 스크립트. **사용자가 호출하지 않아도** 특정 시점에 자동 실행됨.

| 훅 파일                   | 발동 시점                | 역할                                     |
| --------------------- | -------------------- | -------------------------------------- |
| `pre-tool-guard.sh`   | Bash/Edit/Write 직전   | 위험 명령 차단 (rm -rf, force push 등)        |
| `post-edit-lint.sh`   | 파일 수정/생성 직후          | 해당 언어 린터 자동 실행                         |
| `post-git-sync.sh`    | git 명령 직후            | 브랜치/커밋 상태 자동 동기화                       |
| `stop-quality-gate.sh` | Claude가 응답 끝낼 때      | 품질 게이트 (테스트/타입체크) 자동 검증                |

> [!warning] 훅이 막을 때
> 위험한 동작이 차단되면 빨간 메시지가 뜸. 우회하지 말고 **왜 막혔는지** 메시지를 읽고 안전한 방법을 찾을 것. 정말 우회가 필요하면 `/config` 또는 `.claude/settings.json` 의 `permissions.allow` 에 명시 추가.

## 6. 실전 워크플로우 4가지

### 6.1 새 기능 개발 (예: 활동 로그 화면 추가)

```text
1. /clear                                      ← 컨텍스트 정리
2. "활동 로그 화면 추가하려고 해. 백엔드는 GET /api/activity-logs
    페이징 지원하는 API, 프론트는 테이블 + 검색 필터 UI.
    DB 스키마는 docs/activity-log-design.md 참조"
3. (Claude가 core-api + frontend 에이전트 병렬 위임)
4. /test-all                                   ← 검증
5. /security-audit                             ← 보안 점검
6. "커밋해줘"                                   ← 커밋 메시지 자동 생성
```

### 6.2 버그 수정

```text
1. "로그인 시 500 에러 나는 거 고쳐줘. 재현: 이메일에 + 들어가면 발생"
2. (Claude가 로그·코드 분석 → 수정 → 테스트 추가)
3. 차이 검토 후 → "커밋"
```

### 6.3 인프라 변경

```text
1. "@devops nginx에 rate limiting 추가. 분당 60req 초과 시 429"
2. (devops 에이전트가 nginx.conf 수정)
3. "테스트로 nginx -t 돌려봐"
```

### 6.4 진행 상황 파악

```text
"@code-status 지금 4개 레포 어디까지 진행됐는지 요약"
```

## 7. 좋은 프롬프트 vs 나쁜 프롬프트

같은 작업도 어떻게 부탁하느냐에 따라 결과 품질이 달라짐.

| 나쁨                          | 좋음                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| "로그인 만들어줘"                  | "이메일+비번 로그인. JWT 발급은 core-api `/auth/login`. 프론트는 `/login` 페이지에 React Hook Form + zod 검증"        |
| "버그 고쳐"                     | "프로필 페이지에서 이름 30자 넘으면 깨짐. 재현: 닉네임에 한글 31자. 기대: 잘림 처리 또는 검증 에러"                                  |
| "테스트 짜줘"                    | "`UserService.createUser` 의 happy path + 중복 이메일 케이스 + 빈 비번 케이스 단위 테스트. JUnit 5 + Mockito 사용"     |
| "이거 좀 봐줘"                   | "@dinai-ai-api/src/services/rag.py 의 retrieve 함수 — chunk size 결정 로직이 의도한 게 맞는지, 더 나은 방법 있는지 리뷰" |

> [!success] 황금 공식
> **무엇을 + 어디에 + 어떤 제약** 3종 세트를 명시하면 거의 한 번에 원하는 결과가 나옴.

## 8. 자주 막히는 상황

### 8.1 응답이 너무 느림

- `/clear` 로 컨텍스트 초기화
- `/model` 로 Sonnet 또는 Haiku 로 전환 (단순 작업은 Haiku 면 충분)

### 8.2 권한 프롬프트가 자꾸 뜸

- `/permissions` 또는 `.claude/settings.json` 의 `permissions.allow` 배열에 자주 쓰는 명령 추가
- 한 번만 허용 → "Allow once" / 영구 허용 → "Always allow"

### 8.3 에이전트가 다른 폴더 건드림

- `check-ownership` 스킬 호출 → 위반 파일 보고됨
- 해당 변경 되돌리고 올바른 에이전트에게 재할당

### 8.4 한국어 응답을 영어로 함

- 한 번 "한국어로 답해줘" 라고 알려주면 그 세션 동안 유지
- 영구 적용은 `CLAUDE.md` 또는 `~/.claude/CLAUDE.md` 에 "응답은 한국어로" 추가

## 9. 절대 하지 말 것

> [!danger] 금지 사항
> - `.env` 파일에 직접 시크릿 추가 (→ `.env.template` 만 수정)
> - 커밋 메시지에 `claude`, `agent`, `phase`, `step`, `cowork` 같은 AI 도구 용어 포함
> - 하위호환·deprecated·fallback 코드 추가 (이 프로젝트는 신규 구축)
> - `git push --force` / `git reset --hard` 를 Claude에게 시키기 (settings.json 에서 deny 설정됨)
> - `*.md` / `docs/` 파일을 코드 커밋에 끼워 넣기 — 문서는 별도 처리
