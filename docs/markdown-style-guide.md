# 마크다운 작성 가이드 (DINAI 문서 표준)

이 저장소의 모든 `.md` 문서는 옵시디언 + Tistory hELLO 스킨에서 동일하게 보이도록 아래 문법을 따른다. 새 문서/기존 문서 수정 시 **반드시 이 가이드대로 작성**한다.

> 미리보기 환경: 옵시디언 vault에 `obsidian-tistory-hello.css` 스니펫이 켜져 있어야 박스/코드블록/표가 의도대로 보인다.

---

## 1. 콜아웃 (강조 박스) — 4색만 사용

옵시디언 native 콜아웃 문법(`> [!타입] 제목`)을 쓴다. **타입은 아래 4종으로 한정**.

| 의미       | 타입 (alias 포함)                                                            | 색     |
| -------- | ------------------------------------------------------------------------ | ----- |
| 성공/완료/팁  | `success`, `check`, `done`                                               | 🟢 초록 |
| 주의/경고    | `warning`, `caution`, `attention`                                        | 🟡 노랑 |
| 정보/참고/노트 | `info`, `note`, `tip`, `abstract`, `summary`, `tldr`, `example`, `quote` | 🔵 파랑 |
| 위험/에러/버그 | `danger`, `error`, `fail`, `failure`, `missing`, `bug`                   | 🔴 빨강 |

**작성 예시**

```markdown
> [!success] 검증 완료
> 마이그레이션이 정상적으로 적용되었음. 추가 작업 불필요.

> [!warning] DB 스키마 변경 주의
> 이 컬럼은 `core-api` ↔ `ai-api` 양쪽이 참조함. 한쪽만 수정 금지.

> [!info] 참고
> 자세한 구조는 `docs/activity-log-aop-design.md` 참조.

> [!danger] 보안 이슈
> 평문 토큰 저장 코드 발견. 즉시 `security` 에이전트에 보고.
```

**규칙**
- 타입 뒤 한 칸 띄고 **제목**을 같은 줄에 적는다 (생략 가능하지만 가급적 적음)
- 본문은 `>` 로 들여쓰며, 빈 줄(`>` 만 있는 줄)로 문단 분리
- 박스 내부에 리스트/코드/표 모두 가능
- ❌ Tistory `{: .green }` 꼬리표 문법은 **쓰지 않는다** (옵시디언 인식 못 함)
- ❌ 네이티브 옵시디언의 다른 타입(`example`, `quote` 등)도 위 4색 외 별도 색이 없음 — 의미만 맞춰 골라 쓰면 자동으로 파랑 처리됨

## 2. 헤딩 — h2가 섹션 구분의 기본 단위

```markdown
# 문서 제목 (파일당 1개)

## 1. 섹션              ← 자동으로 밑줄 그어짐
## 2. 다음 섹션
### 2.1 하위 섹션
#### 세부 항목 (필요할 때만)
```

- `#` 1개는 문서 최상단 제목 1회만
- `##` 부터 본문 섹션. 옵시디언/스킨 모두 **h2에만 굵은 밑줄**이 들어가므로 시각적 구분에 활용
- 4단계(`####`) 이상은 가급적 피하고, 깊어지면 문서 분할 고려

## 3. 코드블록 — 항상 언어 태그 명시

```markdown
​```typescript
const user = await fetchUser(id)
​```
```

지원 라벨(스킨이 인식해서 자동 대문자 표시): `javascript`/`js`, `typescript`/`ts`, `python`/`py`, `java`, `c`, `cpp`, `csharp`/`cs`, `go`, `rust`/`rs`, `ruby`/`rb`, `php`, `html`, `css`, `scss`, `json`, `yaml`/`yml`, `markdown`/`md`, `bash`/`sh`/`shell`, `sql`, `dockerfile`.

이 외 언어는 표기는 `CODE` 로 떨어지지만 신택스 하이라이트는 정상 동작.

**규칙**
- 언어 태그 **반드시 명시** (없는 코드블록은 `text` 라도 적기)
- 인라인 코드는 백틱 1개: `` `변수명` `` — 함수명/파일경로/명령어/짧은 식별자에 사용
- 긴 명령어/스크립트는 인라인 대신 코드블록으로

## 4. 표 — 헤더 정렬 명시

```markdown
| 항목 | 설명 | 비고 |
|------|------|-----:|
| 좌측 정렬 | 기본값 | 1 |
| 가운데 정렬은 `:---:` | | 2 |
| 우측 정렬은 `---:` | | 99 |
```

- 짝수행 자동 회색 zebra 처리됨 — 별도 강조 불필요
- 셀 안에 줄바꿈 필요하면 `<br>` 또는 셀 분할

---

## 5. 리스트 — 중첩 시 자동으로 마커 달라짐

```markdown
- 1단계 disc (●)
  - 2단계 small square (▪)
    - 3단계는 다시 disc

1. 1단계 숫자
   1. 2단계 알파벳 (a, b, c...)
```

- 들여쓰기는 **공백 2칸 또는 3칸**이 한 단계
- 같은 레벨 항목 사이에 빈 줄 넣으면 옵시디언이 단락으로 처리해 간격 벌어짐 — 의도한 게 아니면 빈 줄 빼기

## 6. 강조 / 링크 / 일반 인용

```markdown
- **굵게** / *기울임* / ~~취소선~~
- 인라인 코드는 `이렇게`
- 외부 링크: [Google](https://google.com)
- 내부 문서 링크: [백로그](백로그.md) — 상대경로 권장
```

콜아웃 타입을 안 붙인 일반 `>` 인용문은 **회색 박스 + 검정 좌측 바**로 출력된다. 단순히 누가 한 말 인용하거나 보조 설명용으로 사용:

```markdown
> "측정할 수 없으면 개선할 수 없다." — Peter Drucker
```

## 8. 작성 체크리스트

문서를 만들거나 수정한 뒤 커밋 전 확인:

- [ ] 파일 최상단에 `#` 제목 1개
- [ ] 섹션 헤딩은 `##` 부터 시작, 번호 매김 (`## 1.`, `## 2.` ...)
- [ ] 강조 박스는 `> [!success/warning/info/danger]` 4색 중 하나
- [ ] 모든 코드블록에 언어 태그 명시
- [ ] 표는 정렬 표시 포함
- [ ] 리스트 중첩 시 들여쓰기 일관 (2칸 또는 3칸 통일)
- [ ] 외부 자료 인용은 일반 `>`, 강조 박스는 콜아웃 — 혼동 금지

> [!warning] 커밋 제외 규칙
> `CLAUDE.md`에 따라 `*.md` 와 `docs/` 파일은 코드 커밋에 포함하지 않는다. 문서만 단독 커밋도 만들지 말 것.
