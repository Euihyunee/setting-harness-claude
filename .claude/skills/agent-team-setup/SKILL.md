# 에이전트 팀 세팅 스킬

이 스킬은 사용자의 프로젝트를 인터뷰한 뒤, Claude Code 에이전트 팀 운용에 필요한
모든 설정 파일을 한 번에 생성합니다.

## 실행 흐름

```
1. 인터뷰  →  2. 팀 설계 제안  →  3. 파일 생성  →  4. 패키징
```

---

## 1단계: 인터뷰

인터뷰는 **두 라운드**로 진행합니다. 모든 질문을 한 번에 던지지 말고, 자연스러운 대화처럼 진행하세요.

### 라운드 1 — 필수 수집 (답변 없으면 진행 불가)

아래 정보를 한 메시지에 간결하게 질문합니다. 이미 대화에서 언급된 내용은 다시 묻지 마세요.

```
프로젝트를 에이전트 팀에 맞게 세팅해 드릴게요. 몇 가지만 알려주세요.

1. 프로젝트 유형: 어떤 종류인가요?
   (예: 웹 풀스택 / 백엔드 API / 프론트엔드 / 모바일 / 데이터/ML / CLI 도구 등)

2. 기술 스택: 주요 언어와 프레임워크는?
   (예: Next.js + FastAPI, React + Spring Boot, Django, Flutter 등)

3. 디렉터리 구조: 주요 폴더 구조를 간단히 알려주세요.
   (예: src/api/, src/components/, tests/ 등 — 대략적으로도 OK)

4. 어떤 작업에 에이전트 팀을 주로 쓰실 계획인가요?
   (예: 기능 개발, 코드 리뷰, 리팩터링, 버그 디버깅 등)
```

### 라운드 2 — 선택 수집 (답변이 없으면 기본값 사용)

라운드 1 답변을 받은 뒤, 불명확한 부분만 추가로 질문합니다.

수집 항목:
- **테스트 프레임워크**: (기본값: 기술 스택에서 추론)
- **DB / 주요 외부 서비스**: (기본값: 없음)
- **CI/CD 도구**: (기본값: 없음)
- **팀원 수 / 협업 방식**: (기본값: 개인 프로젝트)
- **특별히 건드리면 안 되는 파일/경로**: (기본값: .env, secrets/)

## 2단계: 팀 설계 제안

인터뷰 완료 후, 에이전트 팀 구성을 표로 제안합니다. 사용자가 OK를 하면 바로 파일 생성으로 넘어갑니다.

```
수집한 정보를 바탕으로 이런 팀 구성을 제안합니다:

| 에이전트   | 담당 경로              | 역할           |
|-----------|----------------------|----------------|
| frontend  | src/components/ ...  | UI 구현         |
| backend   | src/api/ ...         | API/DB 구현     |
| security  | 전체 (읽기 전용)       | 보안 감사       |

이 구성으로 진행할까요? 추가하거나 빼고 싶은 역할이 있으면 말씀해 주세요.
```

팀 구성 결정 원칙은 `references/agent-archetypes.md`를 참고하세요.

---

## 3단계: 파일 생성

사용자가 팀 구성을 확인하면, 아래 파일들을 **모두 생성**합니다.
생성 기준은 `references/output-templates.md`를 참고하세요.

### 생성 파일 목록

```
{project-name}-agent-setup/
├── CLAUDE.md                          # 팀 공유 컨텍스트 (가장 중요)
├── .claude/
│   ├── settings.json                  # 팀 공유 설정 (git 커밋용)
│   ├── settings.local.json            # 개인 설정 예시 (git 무시)
│   └── agents/
│       ├── {role1}.md                 # 에이전트 역할 정의
│       ├── {role2}.md
│       └── ...
└── README.md                          # 설치 가이드 + 프롬프트 템플릿
```

### 각 파일의 품질 기준

**CLAUDE.md** — 팀원 에이전트가 코드베이스를 탐색하지 않아도 작업을 시작할 수 있을 만큼 충분해야 합니다.
- 반드시 포함: 프로젝트 개요, 기술 스택, 파일 소유권 표, 핵심 규칙, 검증 명령어, 에이전트 소통 규칙
- 절대 포함 금지: 외부에서 알 수 없는 비밀 키, 개인정보

**settings.json** — 최소 권한 원칙 적용. allow는 실제 필요한 명령만, deny는 민감 파일 경로 명시.

**agents/{role}.md** — YAML frontmatter(name, description, tools) + 역할 설명 + 완료 기준(체크리스트) + 소통 규칙.
tools 필드: 구현 에이전트는 `Read, Write, Edit, Bash` / 감사 에이전트는 `Read, Bash`만.

**README.md** — 복사-붙여넣기 가능한 설치 명령어, 실행 프롬프트 3가지 이상, 팀 제어 단축키 표.

## 4단계: 패키징 및 전달

모든 파일 생성 후, 사용자의 프로젝트 루트에 직접 생성합니다.
다음 안내로 마무리합니다:

```
세팅 완료! 확인 사항:

1. CLAUDE.md에서 [실제 경로] 표시 부분을 프로젝트에 맞게 수정

2. Claude Code 실행
   claude --model claude-opus-4-6

3. Shift+Tab → Delegate 모드 전환 후 팀에게 지시
```
